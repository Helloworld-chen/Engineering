# 阶段1 个人模块范围与架构要求

本阶段整理本人负责的 M07（售后审核与客服裁决）和 M08（通知与业务时钟）两个模块的项目上下文，包括模块范围与边界、需求清单、质量要求、开发约束与关键易变点，作为阶段2 方案评审的输入。

项目背景：校园二手商品交易系统面向校内闲置物品交易，买家提交购买申请、付款后由卖家发货，买家收货后平台结算；交易过程中出现退款、申诉、投诉和退货时进入售后流程。本人负责售后处理与全系统的时间、通知基础设施两个模块，系统整体架构与跨模块规则沿用团队总稿。

## 1.1 负责模块与范围边界

M07 负责售后单从受理到裁决的完整生命周期，包括发货前退款受理、卖家审核、买家申诉、客服处理决定、送达后投诉，以及退货验收和升级处理。M07 只作出业务决定，账户与资金的修改由 M02 完成。

M08 负责全系统的统一业务时间、期限存储与到期任务调度、业务事件保存与分发、站内通知与页面状态提示。M08 不持有订单、资金或商品状态，只按事件和期限调用各业务模块的接口。

**表1-1 个人模块的职责与不承担的事项**

| 模块 | 负责内容 | 不承担、由其他模块负责 |
| --- | --- | --- |
| M07 | 售后单与处理决定的记录，退款审核、申诉、投诉、退货验收的状态流转，以及暂停或恢复结算的指令 | 订单状态与资金账目（M02）；角色与数据权限判定（M03）；页面实现（M01） |
| M08 | 统一业务时间、期限任务、事件保存与分发、站内通知与状态推送 | 业务状态是否允许的判断（由各业务模块自行校验）；通知文案的页面渲染（M01） |

本阶段明确以下非目标，避免设计与分工范围扩散：

1. 不接入真实支付、退款、物流与学校统一身份认证，相关操作均使用模拟数据；

2. 不引入消息中间件、独立通知服务或微服务拆分，系统部署为单个后端应用加本地数据库；

3. 不实现多租户、分布式部署与跨机容灾；

4. 不负责前端页面与交互实现，仅向 M01 提供接口字段、失败原因和页面所需数据；

5. 不承担商品审核、举报处理和用户权限数据的维护。
