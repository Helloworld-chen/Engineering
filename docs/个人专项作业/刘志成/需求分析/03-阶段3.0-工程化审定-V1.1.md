### 3.1　用户分析与权限边界

系统共有四类操作者参与本模块的流程：买家只读公开商品并提交举报；卖家维护本人商品并查看审核结论；管理员执行审核与处置；举报人查询本人举报。同一普通账号可以同时是买家与卖家，权限按数据归属判定，不按账号类型判定。

**表3-1　用户与权限边界**

| 用户 | 主要需求 | 权限边界 |
|---|---|---|
| 买家（普通用户） | 浏览在售商品、查看可购买状态、对违规商品提交举报。 | 只读公开商品；只能查询本人举报及其凭证。 |
| 卖家（普通用户） | 查看本人商品的审核结论与理由，修改后重提；查看本人商品被举报的处置结果。 | 只维护本人商品；不得执行审核、处置或下架他人商品。 |
| 管理员 | 审核待发布商品、核查并处置举报、维护商品可见性。 | 可修改审核与出售状态；不得裁定退款、结算等资金事项。 |
| 举报人 | 查询本人举报的处理进度与结论。 | 仅本人举报；凭证仅本人与管理员可见。 |

### 3.2　功能需求

下表为本模块最终的功能需求。优先级「高」表示支撑交易正确性或平台秩序，「中」表示辅助使用；验收要点给出可检查的判定方式。

**表3-2　功能需求**

| 编号与模块 | 功能要求 | 优先级 | 团队来源 | 验收要点 |
|---|---|---|---|---|
| Z01 M05 | 商品列表与详情。公开列表与详情仅展示审核通过且在售的商品，显示名称、价格、描述、图片与可购买状态；待审核、已驳回、违规下架的商品不进入公开结果；已售出商品保留可查询的成交状态说明。 | 高 | FR-05 | 以驳回、下架、已售出三种商品分别请求列表与详情，均不出现可购买入口；已售出详情返回成交状态而非 404。 |
| Z02 M05 | 检索与分页。支持按关键词与分类筛选，按稳定顺序分页；无匹配结果时返回空集合与明确提示；响应回传查询条件与分页信息，便于页面保持查询状态。 | 中 | FR-05 细化 | 同一查询重复执行结果顺序一致；翻页不重复不遗漏；空结果与非法页码返回可识别提示。 |
| Z03 M05 | 可购买状态只读展示。列表与详情返回商品当前的出售状态与占用情况，页面据此显示「可购买 / 已锁定（剩余秒数）/ 已售出」，并在不可购买时给出原因文案。判定与下单校验由 M02 在其事务内完成，本模块不提供校验接口、不参与加锁。 | 高 | V1.2 变更新增；FR-08 | 三种展示状态均可构造并命中；页面显示的剩余秒数与服务端业务时钟一致；M05 不被任何下单事务调用（可通过接口清单核对）。 |
| Z04 M05 | 公开可见性口径。公开列表与检索只包含「审核通过」且「出售状态为在售或已锁定」的商品；待审核、已驳回、已下架、已售出的商品不出现。「锁定」不是商品状态，而是订单租约（M02 写入订单号与到期时间），锁定期间商品仍可见但不可下单。状态迁移由 M04 执行，本模块只按上述组合过滤，不定义迁移规则。 | 高 | FR-06 细化；过滤归 M05，迁移执行归 M04 | 构造「审核中卖家改内容」场景，旧审核提交被拒绝；下架商品在列表与详情中均不可见；状态非法跳转由 M04 拒绝并记录原因。 |
| Z05 M05 | 分类与检索字段维护。维护分类体系与可检索字段（名称、描述、分类）；分类调整只影响后续查询，不改变已提交订单所记录的商品快照。 | 中 | FR-05 细化 | 调整分类后已成交订单仍显示原分类；新增分类后列表可按新分类筛选。 |
| Z06 M06 | 商品审核。管理员查看待审核商品的内容、图片与当前版本，记录通过或驳回的结论与理由；驳回后卖家可修改并重提，重提生成新版本供再次审核。 | 高 | FR-06 | 通过与驳回均产生审核记录；驳回必须填写理由；重提后版本递增且需重新审核。 |
| Z07 M06 | 违规举报。用户对公开商品提交商品号、举报理由与可选凭证图片，系统生成可查询的举报记录，记录举报人与提交时间。 | 中 | FR-07 | 缺理由或商品号不存在时拒绝；同一用户重复举报同一商品按去重规则处理；提交后可在本人列表查到。 |
| Z08 M06 | 举报处置。管理员核查举报，记录「确认违规」或「不成立」的结论与理由，结论绑定被举报内容的版本。确认违规且商品仍在售时，经 M04 下架；商品已售出时只记录处置结论、不改写出售状态（已售出为终态），已有订单与交易记录继续保留，买家从订单进入详情看到的是履约状态而非违规下架。举报流程不裁定退款。 | 高 | FR-07 | 处置后商品从公开列表消失；已有订单仍可查询；结论与理由写入处置记录。 |
| Z09 M06 | 权限与追踪。普通用户不得执行审核与处置；举报人仅能查询本人举报；审核与处置记录保存操作人、时间、前后状态与理由，凭证访问按角色与归属限制。 | 高 | FR-02、FR-07、NFR-08 | 普通账号调用审核接口返回拒绝；他人举报查询返回拒绝；按商品版本可重建完整处置链。 |

### 3.3　质量需求

下表把初稿中「要快」「不能超卖」等表述转化为带条件、指标与验证方法的质量需求。

**表3-3　质量需求与验收标准**

| 编号 | 类型 | 验收标准 | 来源 |
|---|---|---|---|
| NFR-Z01 | 性能 | 在本机演示环境（100 个账号、1000 件商品、500 笔订单）下，10 个并发会话持续 1 分钟：商品列表与详情请求 P95 响应时间 ≤ 2 秒，检索请求 P95 ≤ 2 秒。测试报告记录设备配置与数据规模。 | 团队 NFR-01 细化 |
| NFR-Z02 | 一致性 | 同一商品在审核、下单锁定、下架并发发生时，不得出现「已售出仍可下单」或「已下架仍出现在公开列表」。20 个并发请求争抢同一商品，成功创建有效待付款订单的请求数不超过 1。 | 团队 NFR-03；由 M02 的事务保证，M05 只做展示 |
| NFR-Z03 | 可见性 | 抽样 200 条商品核对：待审核、已驳回、违规下架商品在公开列表与详情中出现次数为 0；下架后 1 秒内（同一请求周期内）不再返回可购买状态。 | FR-05、FR-06 |
| NFR-Z04 | 隐私 | 举报人只能查询本人举报；他人举报查询返回拒绝并写入审计记录；举报凭证仅对举报人本人与管理员开放。测试覆盖换编号越权访问。 | 团队 NFR-02、NFR-07 |
| NFR-Z05 | 可追溯 | 审核与举报处置保存操作人、时间、前后状态与理由，可按商品版本重建处置过程；重复提交处置结论不覆盖原始记录，仅追加新记录。 | 团队 NFR-08 【VP-Adopted】T-03 |

### 3.4　开发约束

**表3-4　开发约束**

| 编号 | 约束类型 | 约束说明 |

### 3.5　外部接口需求

本模块不接入外部系统。依据团队 DC-05，支付、物流与统一身份认证均以本地模拟实现，因此本节不设外部接口需求。模块间接口见个人架构文档 3.6 节。
