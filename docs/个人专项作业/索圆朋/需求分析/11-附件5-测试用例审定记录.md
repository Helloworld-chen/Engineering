## 1 审定目的与依据

**目的**：确认测试用例是否完整覆盖本人负责模块的需求、是否可执行、预期结果是否可判定，并形成修订记录，作为测试执行与验收的依据。

**依据**：

- 《需求规格说明书（V1.5）》S01～S19 需求条目与 3.7 节需求验证方式
- 《需求变更追溯 V1.1》中 CR-01、CR-02 的验收要求
- 质量需求：权限边界、期限准确、事件可恢复、通知去重、请求幂等
- 后端测试类与接口契约（`contracts/openapi.yaml`）

---

## 2 审定方法

采用“检查表 + 逐条走查”的方式，对每条用例检查以下 8 项：

| 编号 | 检查项 | 检查内容 |
| --- | --- | --- |
| C1 | 覆盖性 | 每条需求至少有一个用例；用例与需求的映射无遗漏 |
| C2 | 可执行性 | 前置条件、测试数据、操作步骤是否具体可操作 |
| C3 | 可判定性 | 预期结果是否明确、可观察（状态、字段、错误码、页面文案） |
| C4 | 边界 | 期限边界、重复提交、空值、非法状态 |
| C5 | 异常 | 失败回滚、超时、越权访问 |
| C6 | 独立性 | 用例之间不依赖执行顺序，可单独运行 |
| C7 | 优先级 | 核心链路与异常场景区分优先级 |
| C8 | 一致性 | 编号、术语与需求文档一致 |

---

## 3 逐项检查结果

| 检查项 | 结果 | 说明 |
| --- | --- | --- |
| C1 覆盖性 | **发现缺口** | S07、S11、S12、S13、S14 无对应用例 |
| C2 可执行性 | 通过 | 每条用例均有前置条件与操作步骤 |
| C3 可判定性 | 基本通过 | 状态、错误码明确；TC-05、TC-20 依赖时间推进，已补充判定方法 |
| C4 边界 | 发现缺口 | 期限边界已覆盖（47h/49h），但缺少“恢复计时按剩余时长”的用例（S07） |
| C5 异常 | 基本通过 | 已覆盖越权 403、已发货拒绝、重复请求；失败回滚通过 TransactionRecoveryTest 覆盖 |
| C6 独立性 | **发现问题** | 全量执行时 LogisticsNotificationTest 出现测试间状态污染（BUG-02） |
| C7 优先级 | 未区分 | 用例未标注优先级 |
| C8 一致性 | 通过 | 编号与 S01～S19、CR-01/CR-02 对应 |

## 4 发现的问题与修订

| 编号 | 问题 | 类型 | 影响 | 修订 |
| --- | --- | --- | --- | --- |
| A-01 | S07 恢复收货计时无用例 | 覆盖缺口 | 无法验证“驳回后按剩余时长恢复” | 新增 TC-21 |
| A-02 | S11 凭证上传与查看无用例 | 覆盖缺口 | 凭证权限与关联未验证 | 新增 TC-22 |
| A-03 | S12 客服待办列表无用例 | 覆盖缺口 | 客服只看自己待办的要求未验证 | 新增 TC-23 |
| A-04 | S13 统一业务时间无用例 | 覆盖缺口 | 多模块时间一致性未验证 | 新增 TC-24 |
| A-05 | S14 到期任务执行无用例 | 覆盖缺口 | 任务执行一次、旧代次失效未直接验证 | 新增 TC-25 |
| A-06 | 用例未标注优先级 | 规范性 | 验收时无法区分核心与次要用例 | 在审定结论中说明：TC-01～TC-11 为核心链路，其余为异常与辅助 |

## 6 审定结论

**结论：有条件通过。**

- 修订后本人模块需求全覆盖，用例可执行、预期可判定；
- 核心链路（退款受理、审核、申诉、裁决、退货）与异常场景（越权、重复提交、期限边界）均有覆盖；
- 遗留问题：BUG-02 测试类之间状态污染，不影响功能正确性，已记录并列入后续改进；
- 审定后的用例作为测试执行与验收依据，执行结果见《附件4 功能测试用例与执行记录》第 4 节。
