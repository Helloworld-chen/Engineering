### 1\. 项目简介与个人范围

本项目是校园二手商品交易系统，方便学生发布闲置商品和进行交易。

我负责两个模块：用户身份与权限、商品发布与维护。前者处理账号、登录状态和权限检查，后者处理商品内容、图片以及商品状态的更新。

### 2\. 项目边界

我负责上述两个模块的后端功能，提供接口并参与前后端联调。

统一前端由陈玉豪负责，交易、审核和售后流程由对应成员完成。商品审核决定由审核模块提供，我的模块检查后保存审核结果；交易模块调用商品接口，更新商品的保留、售出或释放状态。

项目在本地运行，支付和物流使用模拟数据，不接入真实支付、快递或学校统一身份认证服务。

### 3\. 功能需求

1\.用户可以注册、登录和退出，查看和修改允许编辑的本人资料。

2\.系统根据登录身份、角色和数据归属检查权限，防止用户操作他人的受限数据。

3\.卖家可以发布商品，填写名称、描述、图片和价格，也可以修改、下架符合条件的本人商品。

4\.商品发布后等待审核，审核通过且符合出售条件时才能购买。

5\.商品模块配合审核和交易模块更新状态，保存时检查商品是否已经变化或被订单占用。

### 4. 质量要求与开发约束

密码不能明文保存，后端需检查访问权限，退出后原会话不能继续使用。

商品修改不能改变已有订单的成交金额。多人同时操作同一商品时，不能互相覆盖数据。操作失败时应说明原因，并保留原有业务数据。应用重启后，已保存的账号、商品和图片引用仍能读取。

项目由四人合作完成，统一使用同一套语言、框架和关系数据库，具体选型待团队确认。前端、后端、数据库和图片均在本地运行或保存，使用 GitHub 记录版本。计划在2026年11月13日前完成开发、测试和提交材料整理。

### 5\. 关键易变点

1. **账号与登录规则。** 注册字段、密码要求、可修改的资料字段和登录有效期尚未确定，后续可能调整。
2. **商品图片规则。** 图片格式、大小和数量限制需要统一，可能随页面设计和存储要求变化。
3. **商品维护规则。** 修改哪些内容需要重新审核、等待审核时是否继续展示，以及被订单占用后能否修改或下架，需要与审核和交易模块共同确认。
