### A2.1　数据表结构

下表为本模块涉及的数据表与关键字段。商品主数据表由 M04 维护，此处只列本模块读取的字段。

**表A2-1　数据表结构**

| 数据表 | 关键字段 | 约束 |
|---|---|---|
| product（M04） | id、title、description、price、image、audit_status、sale_status、version | version 随内容或状态变更递增；本模块只读。锁定字段 locked_until / lock_order_id 由 M02 写入，本模块只读。 |
| review | id、product_id、reviewed_version、admin_id、result、reason、created_at | 同一 product_id 与 reviewed_version 只允许一条有效结论。 |
| report | id、product_id、reporter_id、reason、evidence_id、status、created_at | 同一用户对同一商品的有效举报唯一。 |
| report_decision | id、report_id、admin_id、decision、reason、created_at | 只追加，不更新。 |
| audit_log | id、actor_id、object_type、object_id、action、before_state、after_state、reason、created_at | 只追加；与业务写入同事务。 |
| event_outbox | id、event_type、object_id、object_version、recipient_id、status、attempts | 与业务写入同事务；由 M08 消费。 |

### A2.2　核心流程

审核商品的处理步骤：

review(会话, 商品号, 已读版本, 结论, 理由):

校验管理员权限；结论为驳回时理由必填

开启事务

锁商品记录

读取当前内容版本、审核状态与出售状态

若 已读版本 != 当前版本           -> 回滚，返回「内容已变化，请重新读取」

若 当前审核状态不允许再次审核      -> 回滚，返回状态原因

写入 review 记录（reviewed_version = 已读版本）

调用 M04 更新商品审核状态与出售状态（复用当前事务）

写入 audit_log 与 event_outbox

提交事务

提交后由 M08 读取事件并通知卖家

同一请求标识重复提交 -> 返回首次结果，不重复生成记录

下单校验的处理步骤（由 M02 在事务内调用）：

checkPurchasable(商品号):

读取商品当前审核状态、出售状态、内容版本、锁定截止时刻

待审核/已驳回/已下架 -> (不可购买, 对应原因, 版本, 0)

已售出               -> (不可购买, 已售出, 版本, 0)

已锁定且未到期        -> (不可购买, 已锁定, 版本, 剩余秒数)

在售                 -> (可购买,  无,      版本, 0)

### A2.3　设计验证场景

**表A2-2　验证场景与预期结果**

| 编号 | 场景 | 预期结果 |
|---|---|---|
| TV-01 | 商品被驳回后请求列表与详情 | 公开列表与详情均不出现该商品的购买入口。 |
| TV-02 | 商品在售时两个买家并发下单（由 M02 调用校验） | 仅一个请求通过校验并锁定成功，另一个返回「已锁定」。 |
| TV-03 | 管理员审核期间卖家修改商品内容 | 审核提交被拒，提示内容已变化，商品状态不变。 |
| TV-04 | 用旧版本号重复提交同一审核 | 返回首次结果，不产生第二条审核记录。 |
| TV-05 | 卖家查看本人商品的驳回理由并重提 | 版本递增，商品回到待审核，旧结论作为历史保留。 |
| TV-06 | 举报人查询他人举报 | 返回拒绝，并写入一条审计记录。 |
| TV-07 | 确认违规处置后查询已成交订单 | 商品从公开列表消失，订单仍可查询与履约。 |
| TV-08 | 通知发送失败后重发 | 业务结论保留，不重复下架，通知最终送达一次。 |
