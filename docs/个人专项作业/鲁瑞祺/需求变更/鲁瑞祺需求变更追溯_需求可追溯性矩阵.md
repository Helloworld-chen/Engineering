## 基线差异与验证口径

1. 2026年11月8日，学生确认后续商品功能按队长的接入规则实现。单件直接下单、M02 持有占用表属于编码期间的团队对齐。原多件库存 TC-14～TC-19 保留其编号和历史含义。上表用当前单件用例说明对应覆盖，不能将原多件场景计为已执行。本次专项尚未生成或采纳任何新的变更请求。
2. M03 第一批在 `63c8e65` 对应实现上通过 53 项后端测试。M04 加入后，`f6343e5` 对应实现以正式商品提供者运行 56 项后端测试全部通过。PR 合并前的冲突处理已验证四个 Compose 开关可分别采用默认值和环境变量覆盖。合并后的 `a8e6ab0` 用于固定实现链接，本次矩阵整理未在该合并提交上重跑整套测试。
3. 正式身份、商品行为须设置 `IDENTITY_PROVIDER=real` 与 `PRODUCT_PROVIDER=real`。仓库默认提供者为 `demo`。接口字段及路由可通过[团队接口契约][contract]核对。
4. 后续变更确定后，在受影响行补记需求版本、变更编号及变更状态，同时更新设计决策、实现提交和回归用例。基线矩阵留存供前后对照。
