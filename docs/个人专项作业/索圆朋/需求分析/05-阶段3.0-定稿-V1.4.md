复用结论：依据阶段2.0 第 5 轮的同类产品复用分析，本项目明确采用“担保交易”（平台暂管货款、确认收货后结算）与“举报下架”（沿用商品审核模块）；不采用信用评价与站内聊天，前者需新增评价表与防刷分规则，后者需会话与在线状态，均超出当前工期。

## 3.3 质量需求

质量需求全部改写为可量化、可测试的验收标准。性能指标按课程演示规模设定，具体设备在联调前确认。

**表3-4 质量需求与验收标准**

| 类型 | 需求描述 | 验收标准与验证方法 | 来源/备注 |
| --- | --- | --- | --- |
| 性能 | 售后与通知相关页面响应可接受 | 演示环境（单机）10 个并发会话持续 1 分钟：读取请求 P95 不超过 2 秒，修改请求不超过 3 秒；用接口压测脚本验证 | 原创 |
| 性能 | 通知生成不阻塞业务提交 | 业务提交成功后 1 秒内可查询到对应通知；用时间戳比对验证 | VP-Adopted，T-09 |
| 安全性 | 用户只能操作与查看自己的售后单 | 用两个账号交叉访问对方售后单与通知，请求全部被拒绝；100% 拦截，用接口测试验证 | NFR-02 |
| 安全性 | 客服不能直接执行退款 | 以客服身份调用退款接口被拒绝；通过接口测试与代码审查验证 | VP-Adopted，T-03 |
| 可靠性 | 重启后期限与任务不丢失 | 在期限进行中重启服务，任务在重启后继续执行且不重复；手工场景验证 | NFR-06 |
| 一致性 | 售后决定与资金变动同时生效 | 在资金执行处注入异常，确认售后决定一并回滚；通过故障注入测试验证 | NFR-04 |
| 一致性 | 同一业务请求重复提交只生效一次 | 携带同一请求标识重复提交 3 次，只产生 1 条流水与 1 条通知 | VP-Adopted，T-05 |
| 可用性 | 错误提示能说明原因 | 所有被拒绝的操作返回具体原因（状态不符、超期、无权、文件过大等），逐条核对 | 原创 |
| 易用性 | 新用户能独立完成退款申请 | 不培训情况下，5 名同学中至少 4 人在 3 分钟内完成退款申请 | 原创 |
| 可维护性 | 关键操作可审计 | 审核、裁决、期限变更、通知投递均可在后台查到记录 | NFR-08 |

## 3.5 外部接口需求

本系统不接入真实的外部支付、物流与学校统一身份认证接口。付款、退款、结算使用本地模拟账户与流水记录；物流状态由管理员登记模拟数据；用户身份使用本地账号密码认证。因此本节无外部接口需求。模块之间的内部接口（售后、资金、权限、通知）在设计阶段以内部接口表约定，见架构设计文档的接口部分。

## 3.8 需求来源与修订前后对比

需求来源与获取方法：一是代入用户，以买家、卖家、客服三种身份模拟完整交易与售后流程，记录每一步需要系统提供什么；二是竞品分析，参考常见二手交易平台的下单、担保交易、退款与投诉处理方式，提取可复用的需求模式；三是访谈与讨论，向组内成员和同学确认审核时限、退货验收等规则是否可接受。质量需求来自对演示场景的推演，开发约束来自课程要求与团队分工。

## 附件2 核心用例描述

用例一：发货前退款与申诉

用例名称：发货前退款与申诉　　用例标识：UC-S1　　执行者：买家、卖家、客服

目标：买家在卖家未发货前取消交易并拿回货款；卖家拒绝时由客服裁决。

范围：校园二手商品交易系统——售后模块（M07）、资金模块（M02）、通知与时钟模块（M08）。

质量需求：订单与资金一致；期限计算准确；操作可审计。

前置条件：订单已付款、卖家未发货、平台未结算；该订单无进行中的售后单。

基本流程：

1. 买家提交退款申请并填写理由；M07 锁定订单，复查付款与发货状态，创建售后单并暂停发货与结算。

2. M08 生成卖家审核期限（24 小时），并通知卖家。

3. 卖家在期限内审核：同意则 M07 调用 M02 退款并关闭订单；拒绝则记录理由并开启买家申诉期。

4. 买家在申诉期内提出申诉，M07 将售后单转客服，订单保持冻结。

5. 客服查看双方说明与凭证，作出裁决并记录理由；符合退款条件时由 M07 指示 M02 执行退款，否则恢复订单为待发货。

扩展流程：

3a. 卖家超过 24 小时未处理：M08 到期任务将售后单转交客服。（对应 S03）

4a. 买家放弃申诉或申诉期届满未申诉：M07 恢复订单为待发货。

5a. 客服裁定不退款：订单恢复为待发货，平台继续暂管货款。

异常与结束结果：买家身份不符或订单已发货时，申请被拒绝并提示原因；同一请求重复提交只生效一次；任一环节失败则回滚本次修改，订单与资金保持原状。

对应需求：S01～S06、S13～S18。

用例二：送达后投诉与退货验收

用例名称：送达后投诉与退货验收　　用例标识：UC-S2　　执行者：买家、卖家、客服、管理员

目标：买家在收货后发现商品问题时能暂停结算并获得退货退款；验收异常有升级出口。

范围：售后模块（M07）、资金模块（M02）、通知与时钟模块（M08）。

质量需求：投诉时保存剩余收货时长；驳回后按剩余时长恢复；验收超时不自动退款。

前置条件：商品已送达买家、平台尚未结算；该订单无重复有效投诉。

基本流程：

1. 买家提交投诉并上传照片凭证；M07 保存剩余自动收货时长（不小于 0），暂停自动收货与结算。

2. 客服审核投诉：驳回则恢复剩余计时；支持退货则通知买家寄回。

3. 买家填写退货单号并上传凭证；管理员登记退货已送达卖家，M08 开始计算卖家 24 小时验收期限。

4. 卖家确认收回商品，M07 调用 M02 将暂管货款退回买家账户；系统通知双方。

扩展流程：

4a. 卖家超过 24 小时未验收：M08 到期任务将售后单转客服，平台继续暂管货款。

4b. 卖家提出退货异议：售后单转客服裁决。

2a. 客服驳回投诉：恢复剩余收货时长，重复驳回不再延长。

异常与结束结果：已结算后提交投诉被拒绝；重复登记送达不重复延长验收期限；通知重复投递不重复生成站内通知。

对应需求：S06～S09、S15～S17。
