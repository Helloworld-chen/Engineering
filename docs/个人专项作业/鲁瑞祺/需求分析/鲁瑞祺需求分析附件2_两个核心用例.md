## 用例一 用户注册登录与权限检查

### 基本信息

| 项目 | 内容 |
| --- | --- |
| 用例编号 | UC-L01 |
| 对应模块 | M03 用户身份与权限 |
| 对应需求 | L01～L05，N-L01、N-L02 |
| 主要参与者 | 普通用户 |
| 目标 | 创建普通账号、登录并维护本人昵称，阻止未登录和越权操作 |
| 触发条件 | 用户进入注册或登录页面 |
| 前置条件 | 本地系统可访问；新注册登录名尚未被使用 |
| 成功后置条件 | 账号保存成功；登录会话有效；合法资料修改保存；退出后当前会话失效 |
| 失败后置条件 | 不创建部分账号记录、不修改他人数据、不提升角色权限；无效会话不能访问受限数据 |

### 正常流程

1. 用户填写登录名、密码和确认密码。系统检查登录名为4～20位英文字母、数字或下划线，密码为8～64个字符，两次密码一致。【VP-Adopted】
2. 系统按不区分大小写的规则检查登录名唯一性，保存普通账号及带盐密码散列。确认密码不保存，响应和业务日志不泄露密码或散列。【VP-Adopted：大小写规则及确认密码处理】
3. 用户输入正确登录凭证，系统建立从登录成功起固定2小时有效的会话，访问不会续期。【VP-Adopted】
4. 用户查看本人资料，提交1～20个字符的昵称。系统从会话取得身份，仅允许修改本人昵称，保存后返回结果。【VP-Adopted：昵称范围】
5. 用户再次查询，看到已保存的新昵称。
6. 用户退出，系统使当前会话立即失效；后续使用原会话访问受限接口被拒绝。对应受限推送访问也应停止。

### 异常与替代流程

| 对应步骤 | 情况 | 系统处理及预期结果 |
| --- | --- | --- |
| 1 | 必填缺失、格式或长度非法、两次密码不一致 | 拒绝注册并说明原因，不创建账号 |
| 2 | 登录名重复，包括大小写不同的同名；或同名并发注册 | 重复请求被拒绝，只允许一个同名账号创建成功 |
| 3 | 登录名不存在或密码错误 | 不建立有效会话，提示登录失败 |
| 4 | 昵称为空或超过20个字符 | 拒绝修改，原昵称不变 |
| 4 | 用户尝试指定他人用户号，或修改登录名、角色、余额 | 后端拒绝，原资料、角色和余额不变 |
| 4～5 | 会话已退出或自登录成功起满2小时 | 拒绝受限访问，提示重新登录，不执行资料修改 |

### 验收要点

- 对应规格说明书TC-01～TC-06，检查正常结果、字段边界、并发同名注册、会话时限和越权拒绝。
- 注册完成后正常重启应用，账号仍能查询并使用正确密码登录；重启后是否要求重新建立会话由会话实现方式确定，不把旧会话必须跨重启有效作为本用例要求。
- 使用两个账号验证数据隔离，核对实际保存结果；不能仅凭前端隐藏按钮判断权限正确。

## 用例二 多件商品发布审核与库存协作

### 基本信息

| 项目 | 内容 |
| --- | --- |
| 用例编号 | UC-L02 |
| 对应模块 | M04 商品发布与维护，关联M06审核和M02交易 |
| 对应需求 | L06～L09，N-L03～N-L05 |
| 主要参与者 | 卖家 |
| 协作参与者 | 买家、管理员及审核模块、交易模块 |
| 目标 | 发布并审核多件商品，按交易结果正确占用和转换库存，保护已有订单信息 |
| 触发条件 | 卖家提交商品发布信息 |
| 前置条件 | 卖家已登录；审核和交易接口按团队约定可用；图片属于该卖家并通过校验 |
| 示例数据 | 同款教材3本，单价20元；买家申请购买2本 |
| 成功后置条件 | 商品与图片正确关联；审核和交易记录一致；售出2本后可购买数量为1；原订单商品金额为40元 |
| 失败后置条件 | 不产生部分商品或订单更新，不超卖、不重复扣减、不改变历史订单金额 |

### 正常流程

1. 卖家填写教材名称、描述、单价20元、库存3本，并关联1～5张JPEG／PNG图片，每张不超过5 MiB。系统检查单价为正数且最多两位小数、库存为正整数、图片类型及归属合法。【VP-Adopted】
2. 系统记录当前卖家身份、商品内容及版本，商品进入待审核状态，不在公开列表展示，也不接受新购买申请。
3. 管理员通过审核模块提交针对该商品版本的审核通过结果。商品模块检查调用权限和版本后更新状态；商品未下架且库存足够时可供购买。
4. 买家通过交易模块申请购买2本。提交申请时不占库存，此时仍有3本可购买。【VP-Adopted】
5. 卖家通过交易模块接受申请。系统复查商品状态及库存，在同一次业务操作中占用2本，并按交易模块流程保存订单成交信息；对应商品金额为20×2＝40元。【VP-Adopted：接受时占用及可选数量】
6. 占用后，可购买数量为1、有效占用数量为2、已售数量为0。存在占用期间，卖家不能修改商品内容、价格或下架，也不能手动调整库存。【VP-Adopted】
7. 交易模块按照合法订单流程确认完成出售，调用商品接口将2本有效占用转为已售。结果为占用0、已售2、可购买1，不再次扣减可购买数量。【VP-Adopted】
8. 卖家在无占用且仍有未售数量的条件下，可以修改名称、描述、图片或单价，但不能手动补货或调库存。修改后重新审核并隐藏，已有订单单价20元、数量2和金额40元保持不变。【VP-Adopted】
9. 重新审核通过后，剩余1本按当前状态恢复展示。若卖家在满足条件时下架，商品不再出现在公开列表中，已有订单和历史资料仍保留。

### 异常与替代流程

| 对应步骤 | 情况 | 系统处理及预期结果 |
| --- | --- | --- |
| 1～2 | 图片超限、实际类型非法、引用他人私有图片，或数量、单价不合法 | 拒绝发布并说明原因，不保存部分商品或有效的错误图片引用 |
| 3 | 审核驳回 | 商品不公开可售，卖家可查看理由，并在允许维护时修改重提 |
| 3、8 | 审核或修改携带旧商品版本 | 拒绝覆盖，当前内容与版本不变，提示重新查询 |
| 5 | 商品未审核通过、已下架或操作者无权限 | 接受失败，不产生有效占用或部分订单更新 |
| 5 | 剩余1本，申请购买2本 | 整份接受失败，不自动改为1本，不部分成交。【VP-Adopted】 |
| 5 | 初始3本，两份各买2本的申请并发接受 | 只有一份成功；最终占用2本、可购买1本，另一份提示库存不足。【VP-Adopted】 |
| 5～7 | 同一接受、释放或售出请求重复到达 | 同一业务操作只产生一次数量变化，不能重复占用、释放或售出。【VP-Adopted】 |
| 5～7 | 交易模块确认订单合法取消或失效 | 对应有效占用释放一次；若此前仅占用2本且无其他变化，释放后可购买量恢复为3。取消条件和超时长度由交易负责人确定。【VP-Adopted：释放要求】 |
| 6、8 | 存在有效占用时维护；售罄后修改；任意时候手动调库存 | 拒绝操作，原商品及数量不变。【VP-Adopted】 |

退款、退货不直接等同于取消未完成订单，不能直接调用释放有效占用来恢复已售库存。相关处理须与交易、售后规则一致；本用例不替其他模块确定退款、退货流程。

### 验收要点

- 对应规格说明书TC-07～TC-21，检查发布、审核、修改、下架、占用、释放、售出和持久化结果。
- 初始1本、10份各买1本的申请并发接受时，恰好一份成功，其余失败，不出现负库存。【VP-Adopted】
- 本期不手动补货或调库存；正常交易中保持“可购买数量＝发布时库存总量－有效占用数量－已售数量”，有效占用与已售不重复计算。
- 同时检查接口结果、商品数量和订单记录；每轮并发测试恢复明确的初始数据，尚未运行的场景不得写成通过。
