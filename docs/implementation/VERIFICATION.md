T23 至 T26 中的界面入口、反馈呈现、页面倒计时与浏览器重新连接由前端验证覆盖。测试中的重放模拟响应丢失后再次请求，后端测试未注入网络故障；浏览器测试另行覆盖断线重连和退出响应丢失。JUnit启动恢复用例调用应用启动时使用的同一入口。另外已执行 `sh scripts/test-restart.sh`，在一次性数据库和独立8081进程中真正停止、重启后端，停机期间推进持久化模拟时钟；验证原送达时刻、48小时期限、订单完成及买卖双方余额。并发测试以屏障同时启动两个操作并验证合法终态，未强制每次运行覆盖每一种线程交错。

额外场景包括图片在关联订单前后对不同用户的访问权限、不同用途或持有人及跨订单复用限制、并发关联图片只能成功一次、售后决定与资金回滚、演示重置授权与同标识重试。演示重置 RED 运行命令为 `./scripts/test-backend.sh -Dtest=DemoResetTest`，实现前两个用例均返回 HTTP 404，见 `.local-work/demo-reset-red.log`。

资金故障通过测试库临时 CHECK 约束阻止指定流水类型写入。用例在 finally 中撤销约束，生产实现无需故障开关。首次用触发器试验遇到 MySQL 二进制日志启用后普通账号缺少所需权限，已改用 CHECK 约束。

## 独立审阅后的回归修复

- 付款使用账户锁返回的当前余额，避免MySQL可重复读快照在并发扣款或退款后产生错误判断。两种交错均以真实并发事务复现后通过。
- 会话编号变更和销毁均关闭原SSE连接；切换账号、注册和退出三个场景验证流结束。
- M02应用释放限制的售后决定前，复核售后单已经关闭；卖家拒绝后仍在申诉期的决定不能提前解除发货限制。

## 前端与交付构建

2026年11月7日，`npm test` 的9项单元测试通过，`npm run build` 类型检查与生产构建通过，`npm run test:e2e` 的11项Chromium端到端测试通过。浏览器场景覆盖四角色交易及售后链路、发布审核、注册资料、权限、断线重连、会话失效、退出响应丢失、商品版本冲突保留草稿，以及字段错误的可访问关联和焦点。

独立审阅后修复会话恢复、商品版本冲突和字段错误三个问题，并补充回归。视觉证据覆盖商品列表、商品详情、待付款订单、售后详情的1440、1280及390像素宽度。

Java21后端与Node24前端的Docker镜像均构建成功，Compose已启动真实MySQL、后端及nginx前端。`E2E_EXTERNAL=1 npm run test:e2e` 对实际Compose部署复测，11项全量通过，耗时35.5秒。首轮10项通过、会话场景因失效后的导航链接已移除而超时；改为先进入受保护订单页，再断线清除会话并重连，验证自动登录跳转，复测通过。此次仅调整测试同步方式，产品代码未变。
