# 校园二手商品交易系统

本仓库提供课程演示所用的校园二手交易网站。陈玉豪负责 M01 项目前端与交互、M02 交易履约与资金结算，覆盖个人需求 C01 至 C09。身份、商品、浏览、审核举报、售后和通知时钟通过 M03 至 M08 演示适配器运行，各模块可按接口独立替换。支付、退款、物流和账户余额均为本地模拟。

## 启动

安装并启动 Docker，确认 Docker Compose 可用。进入仓库根目录执行：

```sh
sh scripts/run.sh
docker compose ps
```

打开 [交易网站](http://localhost:5173)。前端通过同源路径 `/api/v1` 访问后端。主机服务端口为前端 5173、后端 8080、MySQL 3308。数据库和上传图片使用 Docker 命名卷。停止服务执行 `sh scripts/stop.sh`，再次启动时继续使用已有数据。

| 用户名 | 角色 |
| --- | --- |
| `buyer` | 陈同学，普通用户，可买可卖 |
| `seller` | 林同学，普通用户，可买可卖 |
| `other` | 周同学，普通用户，可买可卖 |
| `admin` | 商品审核、举报处理及演示管理 |
| `support` | 售后客服 |

演示账户密码均为 `Campus123!`。默认种子含三位同学发布的六件商品。买家和卖家由每笔交易中的参与关系确定；三个普通账号的功能权限相同，均可购买其他用户的商品、发布和管理自己的商品。登录后的“浏览商品”默认排除自己发布的商品，“我的商品”用于查看和管理自己的发布内容。自己的商品详情页显示归属说明，不提供向自己下单的入口。切换角色前可退出登录，也可用独立浏览器会话并行操作。

卖家在“我的商品”中可直接查看待付款、待发货、物流和售后进度，通过“去发货”“处理售后”或“查看订单”进入对应详情。需要卖家操作的商品优先显示，其次为待付款、其他进行中的交易，其余商品排在后面；同组按发布时间倒序。买家下单、付款后页面会实时更新，断线恢复或重新打开页面也会重新读取。取消或付款超时会显示最近订单关闭原因，商品恢复在售；退款完成后商品保留原销售状态。

订单详情的商品信息下展示“交易双方”：卖家和买家的当前昵称、用户编号，以及当前账号的“你”标记。客服在权限允许的关联订单中也能查看双方身份。昵称修改后重新读取会显示新昵称，用户编号保持不变。

登录后，顶部铃铛显示全部未读通知数，超过99条显示“99+”，手机端无需展开菜单即可查看。新消息会弹出可点击的站内提醒，并更新浏览器标签页未读数量；提醒8秒后关闭，鼠标悬停或键盘聚焦时暂停关闭。连续消息合并展示，首次加载历史消息只显示数量。通知页支持单条及全部标为已读，并同步当前账号的其他在线页面；查看或关闭提醒不会自动标记已读。同步失败会提示重试并保留上次可信数量。提醒不播放声音、不申请系统通知权限；网页关闭期间的消息在下次登录时计入未读数量。

物流提醒按订单角色发送：卖家发货及商品送达提醒仅买家收到；买家寄回及退货验收提醒仅卖家收到。另一方订单页面继续实时刷新，不新增未读通知。V2 数据修复会清理可明确识别的历史误发消息；升级前请先备份相关 `outbox` 和 `notifications` 记录，保留原数据库及图片卷。

管理员登录进入 `/admin` 工作台，查看待审核商品和待处理举报；客服登录进入 `/support` 工作台，查看待客服处理、其他处理中及已关闭售后。桌面使用左侧岗位导航，手机使用可收起的导航抽屉。两类工作人员的界面隐藏商品浏览、个人交易和模拟余额，保留通知与账号资料；管理员的演示控制仍在账号资料页。

管理员从商品审核列表进入完整审核详情，核对照片、说明及价格后填写审核理由；商品版本变化时须重新核对。客服从售后处理列表进入申请和关联订单，查看资金、物流及凭证后提交处理决定。岗位列表支持筛选、搜索和每页20条分页，详情返回时保留筛选位置。工作台待办取真实列表统计并展示最早5条；页面可见时每30秒补查，重新聚焦、恢复连接和手动刷新也会更新。岗位首页的待办刷新不会额外生成通知。

1. 买家进入商品详情直接下单，在 2 分钟内付款。付款成功后，货款进入平台暂管。
2. 卖家打开卖出订单，提交物流单号、商品和包装照片。提交成功 10 秒后，系统登记送达并开始 48 小时收货期。
3. 买家确认收货后，系统将暂管货款结算给卖家。未发货退款、送达后投诉及退货路径从订单和售后页面进入。退货寄出后 10 秒登记送达，再开始 24 小时卖家验收期。
4. 演示管理员可通过站内演示入口推进业务时间，也可在明确确认后重置演示业务数据。重置会恢复演示商品、模拟余额和业务时钟，并保留已注册账户。停止服务期间业务时间继续经过，重启后系统补办到期事项。

## 开发与验证

后端使用 Java 21、Spring Boot 4.1.2、MyBatis Spring Boot Starter 4.0.0、MySQL 8.4。前端使用 Node.js 24（至少 24.12.0）、Vue 3、TypeScript 和 Element Plus。

```sh
sh scripts/test-backend.sh
sh scripts/test-restart.sh
cd frontend
npm ci
npm run build
npm test
npx playwright install chromium
E2E_EXTERNAL=1 npm run test:e2e
```

后端测试使用 Docker 中的独立 `campus_market_test` 数据库。浏览器测试需要运行上述演示服务，具体基础地址及环境变量见 [Playwright 配置](frontend/playwright.config.ts)。本地前端开发可在 `frontend/` 执行 `npm run dev`，使用 Vite 的同源代理连接后端。Compose 前端占用 5173 时，可通过 `docker compose stop frontend` 释放端口。

| 验证项 | 结果 |
| --- | --- |
| 后端真实 MySQL 测试 | 50 项通过，失败、错误、跳过均为 0 |
| 前端类型检查、构建和单元测试 | 构建通过，9 项单元测试通过 |
| Playwright 浏览器端到端测试 | Chromium 13 项通过，包含普通用户买卖兼用回归 |

实际验证记录及适用范围见[验证记录](docs/implementation/VERIFICATION.md)。重启测试使用一次性数据库和独立 8081 端口，完成后清理测试资源。
